# 0.90.2 — СЛОВО 2.0 переехало в Slovo_Developer

Первый релиз в репозитории разработки `ArtIgnat2000/Slovo_Developer`. Для ребёнка
ничего не изменилось: код приложения тот же, что в slovo2 0.90.1. Изменились адрес
сайта, база сборки и то, откуда деплой берёт путь.

## 1. Что перенесено

- Весь код и вся история `ArtIgnat2000/slovo2`: ветка `arena/7cdeb11b-slovo2` @ `5d68986`,
  то есть `main` @ `112febf` (0.90.1) и технический аудит `docs/audits/2026-11-01/`.
- Перенос сделан merge-коммитом `4231481`, который соединяет две несвязанные истории:
  - первый родитель — прежний `main` этого репозитория (v0.30.0, `c9f81b6`);
  - второй родитель — slovo2, все 524 коммита.
- Дерево merge-коммита в точности равно дереву slovo2 @ `5d68986`. Файлов прежнего проекта
  не осталось, его история доступна в git через первого родителя.
- PR с переносом нужно сливать **merge-коммитом**. Squash или rebase схлопнут или
  перепишут 524 коммита slovo2.

## 2. Что поправлено под новое имя репозитория

| Где | Было | Стало |
|---|---|---|
| `vite.config.ts` | `REPO_BASE = '/slovo2/'` | `REPO_BASE = '/Slovo_Developer/'` — для локальных `npm run build` и `npm run preview` |
| `.github/workflows/deploy.yml` | база из `REPO_BASE` | `VITE_BASE=/${{ github.event.repository.name }}/`: путь берётся из имени репозитория, и после переименования сайт не опустеет |
| `README.md` | «база /slovo2/» | раздел «Репозиторий», база `/Slovo_Developer/`, грабля «общий origin» |

Без этой правки Pages отдавал бы `index.html` с путями `/slovo2/assets/*`. На
`/Slovo_Developer/` таких файлов нет, и вместо приложения был бы пустой экран.

Тестовые фикстуры с `/slovo2/` и `https://artignat2000.github.io/slovo2/` (`smoke.mjs`,
`prod-boot-check.mjs`, `tests/qr.test.ts` и другие) не трогали. Это произвольные адреса
внутри проверок, от `REPO_BASE` и от сайта они не зависят. Ключи хранения (`slovo2`,
`slovo2-*`) тоже не менялись, о них — в §3.

## 3. Грабля: общий origin с `/slovo2/`

Оба сайта живут на `artignat2000.github.io`. IndexedDB (`slovo2`: прогресс и копии
`slovo2.snap.*`), localStorage (`slovo2-*`), BroadcastChannel `slovo2` и runtime-кэши
привязаны к домену, а не к пути. Service worker и precache у каждого сайта свои: у них
разный scope.

Значит, если открыть сборку из этого репозитория в том же браузере, она прочитает и
перезапишет тот же прогресс, что и `/slovo2/`. Пока версии одинаковые, это незаметно.
Когда формат данных начнёт расходиться (например, в задаче 2.2 плана), это станет
прямым риском для прогресса ребёнка. Так было и с прежним проектом этого репозитория:
его сайт тоже работал на этом домене.

Пока хранилище не разведено: dev-сайт проверять в отдельном профиле браузера или в
режиме инкогнито и не открывать на телефоне, где ребёнок занимается на `/slovo2/`.
Решение владельца — отдельное хранилище для dev-сборки, отдельной задачей (§6).
